## 1. 结论先行

1. **验收未兑现**：held-out acc 在两个口径都没到 p11d §5.1 的门（@8192 +3.1pp 但 p=0.341；
   @12288 +0.7pp 且 p=1.000）。四个 ckpt 全部落在 McNemar 噪声内。
2. **★ 8192 口径下的 +3.1pp 主要是测量假象**：同池、只把执行闸从 8192 松到 12288，
   五个臂一致变好（acc +1.3~+3.8pp、fmt +2.7~+7.5pp）；差中差分解给出
   **约 2.5pp（≈80%）来自 BASE 对紧预算更敏感**（§5）。
3. **真实保留的效应是"预算内交卷"**：8192 下 BASE fmt 89.8 vs 各 ckpt 90.8~93.5；
   松到 12288 后 BASE 追到 97.3，差距消失。它在操作点上是真实能力，但不是推理能力。
4. **条件精度两口径都平坦**（12288: 82.1→83.7；8192: 84.8→84.7），
   **第三次复现 p9 的"瓶颈在条件精度"**：fmt 已近顶（94.5~97.3），reward 没在动推理维度。
5. **过程判据有一条明确不达标**：`M_raw = 300/484 = 62%`，低于 §5.2 的 ≥90% 熔断线——
   宽带（`0.0 1.0`）把课程从 193 扩到 850，代价是近 38% 的组白生成（§3.1）。

## 5. ★ 差中差分解：+3.1pp 里约 80% 是测量假象

| 模型 | 8192 acc / fmt / 条件 | 12288 acc / fmt / 条件 | Δacc | Δfmt | Δ条件 |
|---|---|---|---|---|---|
| BASE | 76.1 / 89.8 / 84.8 | 79.9 / 97.3 / 82.1 | **+3.8** | **+7.5** | −2.7 |
| step100 | 76.1 / 90.8 / 83.8 | 77.8 / 95.2 / 81.7 | +1.7 | +4.4 | −2.1 |
| step200 | 77.1 / 87.0 / 88.6 | 80.2 / 94.5 / 84.8 | +3.1 | +7.5 | −3.8 |
| step300 | 78.5 / 91.5 / 85.8 | 81.6 / 95.6 / 85.4 | +3.1 | +4.1 | −0.4 |
| step400 | 79.2 / 93.5 / 84.7 | 80.5 / 96.2 / 83.7 | +1.3 | +2.7 | −1.0 |

1. **五个臂一致变好** ⇒ 8192 执行闸是**全局压制项**，不是某个臂专属。
   位移量（acc +1.3~+3.8pp、fmt +2.7~+7.5pp）**远超同配置重跑噪声标尺**
   （acc ≤0.4pp、fmt ≤2.4pp，p9 档实测）。
2. **差中差**：8192 口径 step400 vs BASE = **+3.1pp** → 12288 口径 = **+0.7pp**。
   分解 `(BASE 增益 3.8) − (step400 增益 1.3) = 2.5pp`
   ⇒ **约 80% 的表观增益来自 BASE 对紧预算更敏感**。
3. **b/c 一致印证**：step400 的不一致对数两口径相近（54 vs 49），净差从 **+8 塌到 +1**。
4. **真实保留的效应**：`fmt`（预算内交卷）。8192 下 BASE 89.8 vs 各 ckpt 90.8~93.5；
   12288 下 BASE 追到 97.3。**部署若真按 8192 执行，step400 的 +3.1pp 是可用的**，
   但它是"预算合规"能力，不是推理能力。
5. **条件精度两口径都平坦**（84.8→84.7；82.1→83.7），且 12288 口径的 acc 非单调
   （80.2 / 81.6 / 80.5）、step100 还 −2.0pp ⇒ 不支持"训得越久越好"。

> **本节用的是聚合差中差**（两次独立评测的同池读数），**尚未做跨口径的同题配对**。
> 要把它升格为配对结论：
> ```bash
> python -m rlab.analysis --eval-json <口径B表> \
>   --pair-json <口径A表> --pair-a step400_exec12288 --pair-b step400
> ```
> （BASE 同样配一条。注意：跨口径配对要求两表**同批同 gpu_mem**，标签不要与表内已有臂同名。）

> **本轮最贵的一课**：通告预算与执行预算不同值时，两轮的 fmt/acc 差里含一份纯 harness
> 截断位移。接线 2 只把通告接对了，却顺带把执行闸砍了 4096——
> **"接通契约"与"改变实验条件"可以是同一行代码**。

## 8. ★ 奖励接线修复：废调用末段的负优势曾被覆盖成 0（2026-10-21）

**它推翻了本文 §3.2 的一条判读**：sw 修好（`sample_weight ≡ 1`）**不等于**废调用拿到了
负梯度。实锤在 `tool_credit_advantages` 的覆盖分支。

| | 旧行为 | 影响 |
|---|---|---|
| `wasted` 分支 | **无条件** `val = -waste_penalty · L/m` | guard+tcw 把 `tool_waste_penalty` 自动归零 ⇒ `val = -0.0·L/m = 0`，把该段**真实的组内负优势**（6对2错组 = −1.75）改写成 **0** |
| `trunc_tail` 分支 | 一直有 `trunc_tail_penalty > 0` 门槛（`tail_idx` 搜索条件） | 两支语义不一致，只有 wasted 漏了门槛 |

**为什么 sw 救不回来**：`sample_weight` 只决定这一行是否进 loss，**不能恢复已被覆盖掉的
advantage**。CPU 探针（真实 `retool_score_flat → tool_credit_advantages → compute_loss →
backward`）实测：末段 300 token 的 adv `−1.75 → 0.0`，策略梯度**恒 0**。

**边界（不要过度归因）**：被清零的是**废调用那一段**，不是整条轨迹 —— 前缀推理仍按
base_adv 受罚；只有"整条只剩废调用段"时整条 PG 才为 0。C 桶 p11f 实测 **398/505**
条无 boxed，是该形态的高发族。

**修复**：`if action == "wasted" and waste_penalty > 0.0:` —— 惩罚为 0 时不覆盖、落到
`else` 继承 `base_adv`；`waste_penalty>0`（非 guard 档）行为与历史**逐位相同**。

**测试**：旧测试只走到 `sample_weights_for_loss` 就宣称"端到端"，从未把真实 segs 送进
`tool_credit_advantages → loss → backward`，所以漏测。已补该接缝的回归（adv 与梯度双断言）。

**顺带对齐了两条过期断言**（跑本次改动时先红，`git show HEAD` 证实改动前就红）：
① `test_code_wasted_adv_exclusion` 锁的 rollout 内联 sw 片段在 2026-10-20 收敛到
`reward.sample_weights_for_loss` 后已不存在；② `test_attempt_shaping_and_err_tier` 的
passrate 锁用全文 `in` 判断，而提示文案里就写着"原版「可释放…」两个计数已删除"→ 恒假。
两条都改成锁**契约**（规则在 reward 单点 / 去字符串后再判），而不是易变字面量。

   "整组全错被丢弃"的格里，训练完全看不到**。
4. **k=8 的分辨率限制**：0/8 只说明真值 p 的 95% 上界 ≈ 31%。那 17 题里有的真值
   可能是 0.1~0.2（加样本很有效），有的是真 0（要探索/换数据）——**8 样本区分不了**，
   所以这一桶不能直接判成"能力缺口"。

**n=16 的实算收益（纠正 §9.3 的期待）**：inert 组 64.3% → 59.1%（+5pp 可用组），
无梯度的错答质量 19.9 → 17.7（62 里只捞回 2）。**n=16 不是大杠杆**；它的价值集中在
k=1/k=2 那 18 题（p∈[0.1,0.3]）——可用组率 66%/90% → 88%/99%，**定向而非全局**。

**按本直方图排出的顺序**：

| # | 动作 | 依据 |
|---|---|---|
| 1 | **池子按在线率重排**（目标不是"提 M_raw"，而是"让 p≈1 少占算力、让 0/8 有入口"） | dev-like 池 51% 是全对题，纯惰性；doc15 的 75/15/10 正是这个 |
| 2 | **0/8 单独通道**（doc15 阶段 D：固定 16 次新 seed 探索 + 回流） | 扛 27.5% 错答质量且**现在零梯度** |
| 3 | 低-p 混合带定向加次数（k=1,2 的 18 题） | n=8 时 k=1 有 34% 概率整组全错被丢 |
| 4 | **不追 p=7/8** | 44 题只贡献 8.9% 错答质量 |
| 5 | `tool_call_cost` 的 A/B **降到最后** | 按真实轮长 ≈ 0.02×2623/1516 ≈ **0.035**，是 7/8 组正确余量（+0.25）的 14%。机制（token 级项不受 aux 守卫约束）成立，但量级远小于合成例子（m=100 才会翻负） |

## 附：本轮新增的两条通用教训

1. **通告值 ≠ 执行值，二者必须各自有名字。** "模型看到的预算"与"harness 实际放行的预算"
   是两件事；历史上靠"提示写 8192、判据漏 12288"这种**隐式解耦**凑合，一旦把判据接对
   就会静默改变实验条件（§2 / §5）。正解是一个显式旋钮（`tool_execution_budget`），
   且**每轮读数都要报清它等于多少**。
2. **"哪一臂被测量方式坑得多"是排序偏差，不是能力差。** 同一个 harness 参数对 BASE 与
   RL ckpt 的伤害不同（本例 3.8pp vs 1.3pp），就足以在一个真实差异为零的实验里伪造出
   +3.1pp 的名次。**改评估协议时，必须把 BASE 与全部 ckpt 放进同一批重评**
   （差中差分解的前提；只评 step400、复用旧 BASE 的表做不出这个分解）。
